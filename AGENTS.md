# Agents
- Glyphes sheet synchronization tracks session-local field revisions separately from restored/broadcast combat snapshots, hydrates linked counters from sheets, and saves with compare-and-set; default counters and movement must never overwrite existing PDF boxes.
- Glyphes portraits use character.avatar_url and the existing character-avatars storage/cropper; share PDF-space portrait coordinates between preview and export to keep placement consistent.
- Resolve direct token-sheet navigation in the pure tokenSheetTarget helper and reuse the existing full-sheet dialog; this keeps system routing testable without duplicating permissions, saving or realtime logic.
- Use the canvas native double-click event for token-sheet opening independently of movement locks; selection permissions still apply, so locking movement cannot disable authorized sheet access.
- The immersive adventure scene is the default « Tout pour vos aventures » section, lazy-loaded with the classic card grid kept reachable through the « Version classique » button or ?experience=classique; this keeps the new presentation reversible without adding routes.
- Render adventure energy in an isolated SVG overlay measured from artifact positions; restart interrupted transfers from their current head to keep rapid direction changes continuous without dependencies.
- Plan effectif = public.effective_tier(user) (clé partenaire active → premium_mixed, sinon profiles.tier issu de Paddle) ; quotas l'utilisent, le webhook ne touche que profiles.tier — pour ne jamais écraser l'un par l'autre.
- Shared table 3D dice replay the author's broadcast values: viewers pre-simulate the throw offline with cannon-es and relabel the landed face, so results are authoritative without deterministic cross-browser physics; dice geometry lives in components/campaign/dice3d and is shared with the personal roller.
- Live tabletop_state payloads omit unchanged large columns; complete them from the last known state (completeRealtimeRow) and treat an absent column as unchanged, never as empty, so partial GM updates cannot wipe players' boards.
- Tabletop pictures (maps, scene maps, token images) are uploaded with lib/vtt/tabletopImages and stored as URLs, never base64 in tabletop_state; a multi-megabyte row made every load, poll, save and live update resend the image and froze sessions.
- useTabletopSync writes only whitelisted columns (lib/vtt/tabletopMerge), saves tokens/drawings as per-id diffs through the merge_tabletop_items RPC, writes GM-only columns separately, never writes before a confirmed initial load, and rebases local edits on remote rows; this keeps concurrent players from rolling back each other and one refused field from blocking all saves.
- Token/drawing merges carry the active scene the tab last saw and the server refuses them once it changed (SCN01); a scene switch writes tokens with the new scene id in one row update and pending old-scene edits are dropped, so late moves never leak between scenes. A permanent refusal repaints the refused sections from the last confirmed state.
- Glyphes combat persistence writes only tokens changed in the current tab (merge_glyphes_tokens) and a confrontation only from the client that committed it; receivers never rewrite shared state, avoiding N stale concurrent writes.
- Glyphes check results are persisted as one campaign_messages row (dice_roll, metadata.glyphes, validated by the dice trigger) and the dice-channel broadcast only refreshes live views; the chat is the shared source so results reach every member and survive reloads.
